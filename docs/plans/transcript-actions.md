# Plan — Transcript actions and export

**Status:** P0–P3 implemented with automated tests, P4 not started, manual verification pending. Phase 0 is implemented: transcript row indices now map to user-turn ordinals, ambiguous duplicate prompts require an explicit selection, and a successful fork parks the source session's draft and attachments in the existing in-memory draft store. If the source path is unknown, its draft remains in the composer rather than being overwritten. Cancellation leaves the draft untouched. The fork-point picker ignores replies from dismissed or superseded requests. Session switches, new tasks, cloning, folder changes, prompt submission, and explicit process stop/restart or app reload are guarded while a fork reply is pending; the focused rewind tests pass. The remaining process lifecycle paths have now been reviewed: restart paths that bypassed the guard are fixed, quit waits for an in-flight fork (a second request goes immediately), and what stays unguarded is listed below. The full-window pointer-to-fork path and fake-pi process-exit/reconnection tests pass; manual verification with real pi remains. P1 (per-response and visible-transcript Markdown export), P2 (offline PDF export with an opt-in preview) and P3 (regenerate, retry and image resend) are implemented with automated tests; Markdown and PDF now share one opt-in for exporting reasoning and tool output (Settings → General, persisted to `~/.orbit-pi/exports.json`, off by default). P4 is not started. Preserve all existing work, including the intentional deletion of `docs/plans/review-guide.md`.

**Process lifecycle review:** Every path that can replace or move the pi process was checked against `rewind_transition_pending`. ## PDF font and complex-script limitations

- The bundled Noto Sans and Noto Sans Mono faces cover primarily Latin and common punctuation; they are not comprehensive Unicode fonts. PDF export additionally looks for system-installed `Arial Unicode MS`, `Noto Sans CJK SC` and `Noto Sans CJK JP`, in that order. Availability and glyph coverage vary by machine. The current renderer's font discovery skips `.ttc` collections, so a system font can be installed yet unavailable to PDF export. Characters without a usable glyph may be replaced with `?`.
- The current `markdown2pdf` text pipeline emits glyphs per Unicode character instead of performing the substitutions and positioning needed for complex-script shaping. Arabic joining and Indic conjuncts can therefore look wrong even with an appropriate font. Full bidirectional ordering, combining-mark placement, emoji sequences and screen-reader/copy fidelity are not guaranteed; correct extracted text does not prove correct visual rendering. The renderer's math `\\text{}` path separately documents simplified RTL ordering without joining or shaping.
- Deterministic tests use OFL-licensed Arabic and Devanagari fonts **only as test fixtures** to check PDF text, compare emitted glyph counts with a shaping engine, and characterize a logical-order Arabic run against RTL-shaped output. They record the current shaping limitation, not production font coverage or a visual correctness guarantee. Manual cross-platform inspection remains open. Users should inspect the preview and use Markdown export when accurate complex-script output is required.

## Goal and scope

Make actions on messages and conversations discoverable and trustworthy: fork before a prompt, reuse a prompt, and export a response or a conversation. Orbit remains a native GPUI application; pi remains the session source of truth. Export must never send conversation data to a remote service.

## Open decisions

- **Resolved — optional thinking/tool output in exports.** Markdown and PDF share one opt-in (Settings → General, `~/.orbit-pi/exports.json`, off by default). The appendix follows the answer, so a response export still opens with the response; reasoning, tool calls (name, path or command, line delta, failure) and the output pi recorded are included, tool output is cut at 4000 characters with an explicit note, and image-only tool output is noted rather than silently dropped. Fences and inline code grow past backticks in the content. Disclosures and the saved toast name the omission only while it is off.
- **Resolved — quit policy.** Cmd-Q, the menu item, the palette's Quit, and the updater's quit-and-install share one policy. A pending `fork` reply defers the first request; the heartbeat quits once the reply and a regenerate's queued resend have settled, and a second request quits immediately. A cancelled, failed, or lost fork releases the quit through the existing invalidation path. Rationale: quitting mid-fork leaves the branch file pi wrote unadopted by this run and drops the regenerate resend, while refusing outright would trap the app on a fork pi never answers and stall the updater's helper.
- **Not started — active-worktree move.** Moving the worktree in use changes `current_workspace` without moving pi. Deciding between moving the process, refusing while a session is active, and leaving it as a separate fix.
- **Resolved:** PDF backend is the offline `markdown2pdf` renderer, with font/shaping limits documented above; the preview is opt-in and opens the exact temporary PDF; export refuses to overwrite an existing destination.
- **Resolved for pi 1.5:** regenerate and retry branch into a new session file (pi's `fork`) and send the prompt again; there is no in-place regenerate. An error-only assistant row retries from its error card because it has no footer; a failed turn with text keeps the footer action only. `fork` returns only the prompt text, so regenerate resends the images it captures from the transcript, while rewind (edit-and-resend) restores text only.
