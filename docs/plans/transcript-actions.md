**P3 progress:** Verified against pi 1.5.0's RPC contract that no regenerate, retry or edit-and-resend command exists. Orbit now offers **Regenerate** in an assistant response's footer: it reuses the rewind fork-point mapping, sends the fork without opening the picker when the prompt is uniquely identified, and re-sends the reply's text on the new branch. ## PDF font and complex-script limitations

- The bundled Noto Sans and Noto Sans Mono faces cover primarily Latin and common punctuation; they are not comprehensive Unicode fonts. PDF export additionally looks for system-installed `Arial Unicode MS`, `Noto Sans CJK SC` and `Noto Sans CJK JP`, in that order. Availability and glyph coverage vary by machine. The current renderer's font discovery skips `.ttc` collections, so a system font can be installed yet unavailable to PDF export. Characters without a usable glyph may be replaced with `?`.
- The current `markdown2pdf` text pipeline emits glyphs per Unicode character instead of performing the substitutions and positioning needed for complex-script shaping. Arabic joining and Indic conjuncts can therefore look wrong even with an appropriate font. Full bidirectional ordering, combining-mark placement, emoji sequences and screen-reader/copy fidelity are not guaranteed; correct extracted text does not prove correct visual rendering. The renderer's math `\\text{}` path separately documents simplified RTL ordering without joining or shaping.
- Deterministic tests use OFL-licensed Arabic and Devanagari fonts **only as test fixtures** to check PDF text, compare emitted glyph counts with a shaping engine, and characterize a logical-order Arabic run against RTL-shaped output. They record the current shaping limitation, not production font coverage or a visual correctness guarantee. Manual cross-platform inspection remains open. Users should inspect the preview and use Markdown export when accurate complex-script output is required.

## Goal and scope

Make actions on messages and conversations discoverable and trustworthy: fork before a prompt, reuse a prompt, and export a response or a conversation. Orbit remains a native GPUI application; pi remains the session source of truth. Export must never send conversation data to a remote service.

## Phases

1. **P0 — Reliable fork (implemented; manual verification not started).** Correct the mapping between transcript rows and pi's fork points. 2. **P1 — Markdown export (implemented; verification not started).** The response footer offers per-response export, and the command palette offers visible-transcript export. The native asynchronous save dialog snapshots text before opening; background writes refuse overwrites. Thinking and tool output are omitted, and image attachments are noted rather than embedded. 3. **P2 — PDF export (implemented; cross-platform verification not started).** Offline PDF export and opt-in system-viewer preview exist for a response or visible conversation, including attached raster images. Automated tests cover cancellation and representative layout and Unicode cases. Manually inspect native dialogs, previews, output and font fallback on macOS, Windows and Linux before marking complete.
4. **P3 — Historical actions (implemented; verification and translations not started).** pi 1.5 has no regenerate/retry/edit command; regenerate and retry are a fork into a new session followed by a prompt, and edit-and-resend remains rewind with the prompt handed back to the composer. A response's footer regenerates it, and an error-only turn retries from its error card. Regenerate resends the prompt's text and attached images; rewind hands back text for editing. Ambiguous or compacted prompts are refused rather than guessed, and a running session must be stopped first. Never imply a destructive in-place edit when pi creates a fork. Preserve unsent drafts and attachments, and require explicit user action before replacing either. Tests cover failures, cancellation, busy sessions, session changes, duplicate prompts and process loss. Remaining: manual GUI verification with real pi and translated strings.
5. **P4 — Navigation and sharing (not started).** Design persistent bookmarks/outline after stable entry identities are available. Compare forks only after defining a comparison model. A hosted sharing service is out of scope unless separately approved; local export does not upload data.

## Open decisions

- **Not started — optional thinking/tool output in exports.** Markdown and PDF currently omit both and say so. Undecided whether to add an opt-in.
- **Not started — quit policy.** Cmd-Q and the updater's quit-and-install are final today; undecided whether either should wait for an in-flight fork.
- **Not started — active-worktree move.** Moving the worktree in use changes `current_workspace` without moving pi. Deciding between moving the process, refusing while a session is active, and leaving it as a separate fix.
- **Resolved:** PDF backend is the offline `markdown2pdf` renderer, with font/shaping limits documented above; the preview is opt-in and opens the exact temporary PDF; export refuses to overwrite an existing destination.
- **Resolved for pi 1.5:** regenerate and retry branch into a new session file (pi's `fork`) and send the prompt again; there is no in-place regenerate. An error-only assistant row retries from its error card because it has no footer; a failed turn with text keeps the footer action only. `fork` returns only the prompt text, so regenerate resends the images it captures from the transcript, while rewind (edit-and-resend) restores text only.
